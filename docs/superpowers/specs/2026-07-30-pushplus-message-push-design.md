# PushPlus 建仓机会推送设计

## 目标

在不改变现有技术指标公式和入场判断的前提下，每小时扫描美股和港股，并通过 PushPlus 将符合条件的股票逐只推送给当前绑定的微信用户。

## 已确认选择

本方案采用 PushPlus 一对一消息 API。用户已完成实名认证、取得个人 Token，并通过手工请求成功收到测试消息。

现有微信公众号测试号发送器继续保留，避免破坏已完成的测试能力；正式后台任务改用 PushPlus，不再依赖服务号、模板 ID 或 OpenID。

## 配置

新增环境变量：

```env
ENABLE_MESSAGE_PUSH=false
MESSAGE_PUSH_PROVIDER=pushplus
PUSHPLUS_TOKEN=
```

- `ENABLE_MESSAGE_PUSH=false` 时，不预热消息推送缓存、不启动定时扫描、不调用 PushPlus。
- 开启后如果 `PUSHPLUS_TOKEN` 缺失，只记录配置错误并跳过消息发送，不影响 FastAPI 和现有页面/API。
- Token 只能从后端环境变量读取，日志不得输出完整 Token。

## PushPlus 消息发送

使用：

```text
POST https://www.pushplus.plus/send
Content-Type: application/json
```

请求字段：

- `token`：环境变量中的个人 Token；
- `title`：包含市场、股票、方向和价格的简短摘要；
- `content`：HTML 格式的完整指标内容；
- `template`：固定为 `html`；
- `channel`：固定为 `wechat`。

成功标准为 HTTP 请求成功且响应 JSON 中 `code == 200`。

网络超时、连接失败、HTTP 5xx 或 PushPlus 明确的临时服务异常，单条消息最多尝试 3 次。Token 无效、未实名、接口权限或参数错误等永久错误不重试。每条股票发送失败不能阻断同市场其他股票或另一个市场。

## 消息内容

每只符合条件的股票单独发送一条，不设置详情链接，不跨小时去重。

标题示例：

```text
美股｜AAPL Apple｜做多｜现价 210.50
```

正文至少包含：

- 提醒类型：建仓机会提醒；
- 市场；
- 股票代码和名称；
- 建仓方向；
- 当前实时价格和币种；
- 布林上轨、中轨、下轨；
- MA20 方向；
- ATR14；
- 突破幅度；
- 中国时间扫描时间。

建仓方向只从现有结果派生：

- MA20 上升、当前价格位于布林下轨及以下、没有反转趋势：`做多`；
- MA20 下降、当前价格位于布林上轨及以上、没有反转趋势：`做空`。

方向字段不得参与或改变现有 `is_suitable_for_entry` 计算。

## 调度和交易日

第一版使用 FastAPI 单进程内后台任务，每个中国时间整点执行一次。应用关闭时正常取消任务，同一时刻只允许一轮扫描运行；上一轮未结束时跳过并记录日志。

每轮分别判断 US 和 HK：

1. 将服务器时间转换到 `Asia/Shanghai`；
2. 使用中国日期调用长桥 `QuoteContext.trading_days`；
3. 每个市场最多尝试 3 次；
4. 接口连续异常后，按中国时间周一至周五降级；
5. 接口正常返回休市时不得使用工作日规则覆盖；
6. 被判断为交易日的市场全天每小时扫描，以覆盖美股夜盘。

US 与 HK 独立运行。任意一个市场可用就继续该市场；两个市场都不可用才结束本轮。

## 市场缓存

复用已批准的 `message_push_market_cache` 设计：

```python
message_push_market_cache = {
    "US": {
        "cache_ready": False,
        "trade_date": None,
        "error": None,
        "bars": {},
    },
    "HK": {
        "cache_ready": False,
        "trade_date": None,
        "error": None,
        "bars": {},
    },
}
```

FastAPI 启动时仅在 `ENABLE_MESSAGE_PUSH=true` 时分别预热 US/HK。每个市场最多初始化 3 次，使用临时字典构建后原子替换。一个市场失败不影响另一个市场，也不阻止 FastAPI 启动。

每小时重新运行各市场 Screener，条件固定为：

- 最低市值：2000 亿；
- 最低月均成交量：1000 万。

缓存键按市场、交易日期和股票代码管理。当天新进入 Screener 且未命中的股票按需补查最近 30 根日 K；退出 Screener 的股票当天不删除。市场日期变化时只清理该市场缓存。

## 指标与推送条件

扫描复用现有指标函数和现有判断门槛，不复制或修改公式。历史数据继续排除当日未完成日 K。

本轮只推送：

```text
is_suitable_for_entry == "是"
```

没有任何匹配股票时不发送“暂无机会”等空消息，只记录零结果日志。相同股票下一小时仍符合条件时使用最新价格重新发送。

## 日志与故障隔离

日志覆盖：

- 每次交易日查询尝试及降级来源；
- 每次缓存初始化尝试、股票数、耗时与最终错误；
- Screener 数量、缓存命中数、补查数、完成计算数和匹配数；
- 每条消息的市场、股票代码、方向、尝试次数、PushPlus 返回码、成功或失败和耗时；
- 整轮任务开始、结束、耗时或并发跳过原因。

日志不得包含完整 Token 或其他密钥。

单只股票计算失败、单条消息失败、单个市场失败都只影响对应单元。后台任务异常不得导致 FastAPI 退出。

## 运行边界

第一版仅支持单 FastAPI Worker。多 Worker 会各自持有内存缓存并重复执行定时任务；部署时必须保持一个 Worker。未来需要多 Worker 时，应将扫描任务拆到独立进程或引入分布式锁和共享缓存。

## 测试范围

自动化测试覆盖：

- PushPlus 请求格式、成功响应、临时错误重试和永久错误不重试；
- Token 不进入日志；
- 关闭开关时不预热缓存、不启动任务、不发送消息；
- US/HK 独立初始化和独立失败；
- 单市场最多初始化 3 次且不发布半成品；
- 当前交易日缓存已准备时不重复初始化；
- 新交易日仅清理对应市场；
- Screener 新股票只补查缺失日 K；
- 中国日期交易日判断、三次重试、工作日降级和正常休市不降级；
- 每小时整点触发、并发轮次跳过、生命周期退出时停止；
- 只推送适合入场股票，做多/做空映射正确；
- 一只股票一条、零匹配零发送、下一小时允许再次发送；
- 单只股票、单条消息和单个市场失败均不会阻断其他处理；
- 所有既有指标公式测试和 API 测试继续通过。
