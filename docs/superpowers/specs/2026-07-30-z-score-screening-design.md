# Z-Score 股票筛选与建仓判断设计

## 目标

为日线、分时和消息推送增加 Z-Score 指标，并用 Z-Score 统一替代 BOLL 轨道作为以下业务行为的准入条件：

- 日线和分时股票入选；
- 逆转趋势判断；
- 是否适合建仓判断；
- 消息推送的做多、做空方向判断。

结果页不再提供信号筛选，也不再展示原有 BOLL 上穿、下击信号。BOLL 上中下轨继续保留为参考指标；现有 BOLL 计算函数和历史信号数据无需删除。

## 指标定义

设判断时使用的当前价格为 `P`，判断日前20个完整交易日的收盘价为 `C1 ... C20`：

```text
MA20 = (C1 + C2 + ... + C20) / 20

SD20 = sqrt(
  ((C1 - MA20)² + ... + (C20 - MA20)²) / 20
)

Z-Score = (P - MA20) / SD20
```

SD20 使用总体标准差，与现有 BOLL 标准差口径一致。MA20 和 SD20 使用完全相同的20个交易日窗口，均不包含当前判断日。

当 `SD20 = 0` 时，Z-Score 定义为 `0`，避免除零。该股票不会满足正负1.5的入选阈值。

## 时间与价格口径

所有窗口均按交易日序列计算，不按自然日计算。

### 日线

- 判断日 `T` 是最新已收盘日 K 的交易日；
- 当前价格 `P` 取 `T` 日收盘价；
- MA20 和 SD20 使用 `T` 之前20个完整交易日，不包含 `T`；
- Z-Score 与其他日线指标一起落库。

### 分时

- 判断日 `T` 是当前市场交易日；
- 当前价格 `P` 取最新实时价；
- 如果行情接口返回 `T` 日尚未收盘的日 K，必须排除；
- MA20 和 SD20 使用 `T` 之前20个完整交易日；
- Z-Score 实时计算，不写入日线指标表。

### 消息推送

- 当前价格 `P` 取消息扫描时的最新实时价；
- 历史窗口与分时保持一致；
- 复用公共指标计算结果，不自行重复计算 Z-Score。

## 股票入选规则

日线和分时列表只返回满足以下任一条件的股票：

```text
Z-Score >= 1.5
或
Z-Score <= -1.5
```

阈值包含等号。Z-Score 为空或介于 `-1.5` 与 `1.5` 之间时不进入结果。

原有 `upper_breakout`、`lower_breakdown` 或 `signal_type != none` 不再作为日线和分时结果的准入条件。BOLL 轨道位置也不参与新的入选规则。

## 逆转趋势

做多逆转：

```text
MA20方向 = 上升
且 Z-Score <= -1.5
且 当前价格 < 前10日最低点 - 0.25 × ATR14
```

做空逆转：

```text
MA20方向 = 下降
且 Z-Score >= 1.5
且 当前价格 > 前10日最高点 + 0.25 × ATR14
```

任一组条件全部成立时，`是否存在逆转趋势 = 是`；否则为 `否`。ATR 调整后的价格阈值继续使用严格小于或严格大于。

## 是否适合建仓

适合做多：

```text
MA20方向 = 上升
且 Z-Score <= -1.5
且 是否存在逆转趋势 = 否
```

适合做空：

```text
MA20方向 = 下降
且 Z-Score >= 1.5
且 是否存在逆转趋势 = 否
```

任一组条件全部成立时，`是否适合建仓 = 是`；否则为 `否`。MA20方向为 `需人工判断` 时，逆转趋势和是否适合建仓均为 `否`。

## 公共计算与数据流

扩展 `indicator_service.calculate_historical_setup` 及其结果对象，使一次公共计算同时返回：

- MA20方向；
- MA20；
- SD20；
- Z-Score；
- ATR14；
- 前10日高低点；
- BOLL 三轨；
- 是否存在逆转趋势；
- 是否适合建仓。

MA20 和 SD20 作为公共计算的内部或结果数据使用；本次必须对外新增的业务字段为 `z_score`。日线同步、分时筛选和消息推送必须复用该公共函数，避免各入口产生不同口径。

### 日线

日线同步将 `z_score` 写入 `stock_metrics_daily`。重复同步同一交易日时必须更新该字段。现有数据库通过幂等的增量加列方式兼容，不重建或删除表。

日线查询从最新交易日的落库结果中筛选 `z_score >= 1.5` 或 `z_score <= -1.5`，不再按 BOLL 信号筛选。

### 分时

分时流程继续实时拉取候选股票、实时价和日 K。排除当前市场交易日的日 K 后，使用公共函数计算 Z-Score，并只保留满足正负1.5阈值的结果。

### 消息推送

消息推送继续以 `是否适合建仓 = 是` 为发送前提。方向改为：

```text
MA20上升 且 Z-Score <= -1.5：做多
MA20下降 且 Z-Score >= 1.5：做空
```

移除基于 BOLL 上下轨的二次准入判断。推送正文增加 Z-Score，展示两位小数；BOLL 三轨仍作为参考信息保留。

原有“突破幅度”基于 BOLL 计算，已不再代表新的准入程度。消息推送中将其替换为 Z-Score，不再展示 BOLL 突破幅度。

## API 与前端

### API

日线和分时结果新增：

```text
z_score: number | null
```

从日线和分时 API 中移除 `signal_type` 查询参数。响应中的 `signal_type` 字段不再作为前端契约的一部分。

API 对不满足 Z-Score 阈值的股票不返回结果，因此前端无需再次执行同一筛选。

### 前端

删除：

- “信号类型”筛选控件；
- 请求中的 `signal_type` 参数；
- 结果表“信号”列；
- 对应的 BOLL 信号类型与格式化逻辑。

增加“Z-Score”结果列，数值保留两位小数；空值显示 `-`。日线和分时使用同一展示格式。

## 数据不足与异常处理

- 少于20个有效历史交易日时 Z-Score 为空；
- 公共历史指标仍遵循现有的整体数据完整性约束；缺少计算逆转和建仓所需的25个历史交易日时，相关公共结果保持空值；
- Z-Score 为空的股票不进入日线或分时结果；
- `SD20 = 0` 时 Z-Score 为 `0`；
- 单只股票数据不足不应中断整批筛选；
- 重复日 K 按交易日期去重后计算。

## 兼容与清理范围

- 不删除数据库中已有 `signal_type` 和 BOLL 信号列，以避免破坏历史数据和扩大迁移风险；
- 日线同步可以继续计算并保存原有 BOLL 信号，但网页查询、分时查询和消息推送不得依赖其作为准入条件；
- API 调用方不再需要传递 `signal_type`；
- README 中关于 BOLL 信号筛选的产品说明同步更新为 Z-Score 筛选。

## 测试

### 公共指标

- MA20 与 SD20 使用同一组、排除判断日的20个收盘价；
- SD20 使用总体标准差；
- 正 Z、负 Z 和 Z 为零；
- `SD20 = 0` 时 Z-Score 为零；
- Z 恰好等于 `1.5` 和 `-1.5` 时包含在阈值内；
- 逆转趋势使用 Z 条件，不依赖 BOLL 轨道；
- 建仓判断使用 Z 条件，不依赖 BOLL 轨道；
- MA20持平时不产生建仓机会；
- 历史不足和重复交易日处理。

### 日线

- 同步写入并在重复同步时更新 Z-Score；
- 旧数据库增量增加 `z_score` 列；
- API 只返回 `|Z| >= 1.5` 的最新日线结果；
- API 不要求 `signal_type` 参数；
- BOLL 信号为 `none` 但满足 Z 阈值的股票仍会返回。

### 分时

- 使用实时价计算 Z-Score；
- 排除当前交易日未收盘日 K；
- 只返回 `|Z| >= 1.5` 的股票；
- BOLL 未穿轨但满足 Z 阈值的股票仍会返回；
- 每次请求继续使用最新行情，不依赖日线落库的 Z-Score。

### 前端

- 不显示信号筛选；
- 请求不发送 `signal_type`；
- 不显示“信号”列；
- Z-Score 正确保留两位小数，空值显示 `-`；
- 删除列后空表状态的列跨度正确。

### 消息推送

- 做多和做空方向由 MA20方向与 Z 阈值决定；
- BOLL 位置不再二次拦截符合条件的机会；
- 逆转股票不推送建仓机会；
- 正文展示 Z-Score，不再展示 BOLL 突破幅度；
- 网页、分时和消息推送对同一组行情得到一致的判断结果。
