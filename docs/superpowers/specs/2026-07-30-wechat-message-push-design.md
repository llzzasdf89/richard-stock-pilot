# 微信公众号建仓机会推送设计

## 目标

在现有盘中指标计算逻辑不变的前提下，每小时扫描美股和港股，并将适合建仓的股票通过微信公众号逐只推送给一个固定接收人。

## 本次范围

本次设计包含：

- 单个固定微信公众号接收人；
- 每小时后台扫描；
- 美股、港股独立扫描和推送；
- 只推送 `is_suitable_for_entry == "是"` 的股票；
- 做多和做空机会都推送；
- 每只股票单独发送一条消息；
- 微信 `access_token` 缓存；
- 消息发送重试和日志。

本次不包含：

- 多用户绑定；
- 微信 Webhook；
- 接收用户消息；
- 详情页面或跳转链接；
- 跨小时业务去重；
- 推送结果数据库表。

## 配置

使用以下环境变量：

```env
ENABLE_MESSAGE_PUSH=false
WECHAT_APP_ID=
WECHAT_APP_SECRET=
WECHAT_TEMPLATE_ID=
WECHAT_TOUSER_OPENID=
```

`ENABLE_MESSAGE_PUSH=false` 时，不初始化消息推送市场缓存、不启动定时扫描，也不调用微信接口。

开启消息推送时，如果微信配置不完整，应记录明确错误并跳过消息发送，不影响现有页面和 API。

## 定时调度

第一版使用 FastAPI 进程内定时任务，每个中国时间整点执行一次。

定时任务与 `message_push_market_cache` 位于同一个 FastAPI 进程，避免跨进程共享内存。应用关闭时必须正常停止定时任务。

每轮开始时：

1. 使用中国时间确定当前日期；
2. 分别通过长桥 `QuoteContext.trading_days` 判断美股和港股是否为交易日；
3. 交易日接口按市场最多尝试 3 次；
4. 连续失败后，按中国时间周一至周五进行降级判断；
5. 非交易日市场跳过本轮扫描；
6. 交易日市场检查并准备自己的缓存。

只要中国日期被判断为对应市场的交易日，就全天每小时扫描，不再限制盘前、正常交易、盘后或夜盘的具体时间。这样可以覆盖美股夜盘机会。

同一时刻只允许一轮消息推送扫描运行。如果上一轮尚未结束，下一轮直接跳过并记录日志。

## 市场可用性

美股和港股独立运行：

- US、HK 都可用：两个市场都扫描和推送；
- 只有 US 可用：只扫描和推送美股；
- 只有 HK 可用：只扫描和推送港股；
- 两个市场都不可用：结束本轮任务并记录日志。

一个市场的缓存或行情查询失败，不得阻断另一个市场。

## 股票筛选和指标

每个市场使用以下 Screener 条件：

- 最低市值：2000 亿；
- 最低月均成交量：1000 万。

对于 Screener 返回的股票：

1. 从 `message_push_market_cache` 获取历史日 K；
2. 缓存未命中时补查最近 30 根日 K；
3. 批量获取最新实时价格；
4. 使用现有公式计算布林带、MA20、ATR14、前 10 日高低点、反转趋势和是否适合入场；
5. 只保留 `is_suitable_for_entry == "是"` 的股票。

不得修改任何现有指标公式和判断门槛。

## 建仓方向

消息中的“建仓方向”由现有判断分支派生，仅用于展示：

- MA20 上升、当前价格位于布林下轨及以下、没有反转趋势：`做多`；
- MA20 下降、当前价格位于布林上轨及以上、没有反转趋势：`做空`。

建仓方向不能引入新的计算公式，也不能改变 `is_suitable_for_entry` 的结果。

## 消息粒度和内容

每只符合条件的股票单独发送一条消息。消息不设置详情链接。

本轮没有任何 `is_suitable_for_entry == "是"` 的股票时，不调用微信消息接口，不发送“暂无机会”等空结果通知，只记录本轮零结果日志。

消息至少包含：

- 提醒类型：建仓机会提醒；
- 市场；
- 股票代码；
- 股票名称；
- 建仓方向：做多或做空；
- 当前实时价格和币种；
- 布林上轨；
- 布林中轨；
- 布林下轨；
- MA20 方向；
- ATR14；
- 突破幅度；
- 中国时间扫描时间。

示例：

```text
建仓机会提醒

市场：美股
股票：AAPL.US / Apple
建仓方向：做空
当前价格：215.30 USD
布林上轨：212.80
布林中轨：205.60
布林下轨：198.40
MA20方向：下降
ATR14：4.26
突破幅度：1.17%
扫描时间：2026-07-30 22:00
```

实际字段需要映射到公众号后台审核通过的模板变量。模板字段长度不足时，优先保留股票代码、方向、价格、关键指标和扫描时间。

## 不做跨小时去重

本次不做业务去重。

如果同一只股票连续多个小时满足建仓条件，每个小时都重新发送一条消息。每轮都使用当时最新价格和重新计算后的指标值，扫描时间用于区分不同轮次。

## 微信访问令牌

后端使用 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET` 获取微信公众号 `access_token`。

令牌只保存在进程内存：

- 有效期内复用；
- 在微信返回的有效期之前预留安全时间主动失效；
- 获取令牌失败时最多尝试 3 次；
- 每次成功和失败都记录日志；
- 日志不得包含 AppSecret 或完整 access token。

## 消息发送和重试

每只股票对应一次微信模板消息请求。

单条消息最多尝试 3 次，但重试仅用于网络超时、连接失败和明确的临时服务错误。参数错误、OpenID 错误、模板错误和权限错误不得盲目重试。

不做跨小时业务去重，不等于允许同一轮无限重发。每次尝试都要记录微信返回码和错误信息；成功后立即停止重试。

## 日志

每轮扫描至少记录：

- 任务开始和结束时间；
- 市场；
- 交易日判断结果及来源；
- Screener 股票数；
- 缓存命中数和补查数；
- 完成指标计算的股票数；
- 适合建仓的股票数；
- 推送成功数；
- 推送失败数；
- 总耗时；
- 是否因上一轮未完成而跳过。

每条消息至少记录：

- 市场；
- 股票代码；
- 建仓方向；
- 当前尝试次数；
- 微信返回码；
- 微信消息 ID（如果返回）；
- 成功或失败；
- 错误信息；
- 耗时。

日志不得记录 AppSecret、完整 access token 或其他敏感凭据。

## 故障隔离

- 单只股票计算失败：记录错误并继续处理其他股票；
- 单条微信消息失败：记录错误并继续发送其他股票；
- 单个市场失败：另一个市场继续；
- 两个市场都失败：结束本轮，不影响 FastAPI；
- 微信接口不可用：本轮行情计算可以完成，但消息发送失败并记录日志；
- 定时任务异常不能导致 FastAPI 进程退出。

## 测试范围

自动化测试需要覆盖：

- 关闭开关时不启动定时任务和微信调用；
- 每个中国时间整点触发一次；
- 上一轮未结束时跳过新一轮；
- 美股和港股独立执行；
- 两个市场都不可用时不发送；
- 只推送 `is_suitable_for_entry == "是"` 的股票；
- 做多、做空方向映射正确；
- 每只股票单独发送一条；
- 交易日全天每小时扫描，不受具体交易时段限制；
- 本轮没有合适股票时不调用微信发送接口；
- 同一股票下一小时仍满足时再次发送；
- 消息没有详情链接；
- access token 在有效期内复用；
- access token 获取失败最多尝试 3 次；
- 单条消息临时错误最多尝试 3 次；
- 永久性微信错误不重试；
- 单条失败不影响其他股票；
- 成功和失败日志完整；
- 所有现有指标和 API 测试继续通过。
